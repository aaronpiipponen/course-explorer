# Capture and normalization

The ingestion package captures the public curriculum source into immutable evidence, then converts a completed capture into the normalized official catalogue in one transaction.

## The source adapter and the capture service

`src/course_explorer/ingestion/source.py` declares the family contracts and the neutral capture seam. `SisuSource` names the Sisu reads the shared capture driver consumes: `get_curriculum_periods`, `iter_course_version_refs`, `iter_module_version_refs`, `iter_course_versions`, `iter_module_versions`, `get_course_group_versions`, `get_module_group_versions`, `iter_course_group_versions`, and `iter_module_group_versions`. `CapturedResponse` pairs one request path and its ordered request parameters with the exact response body. `SourceResponse` pairs that evidence with a validated value, and `KoriRequestError` and `KoriContractError` separate a failed request from a violated source contract. `SourcePeriod` carries a published period's id and its inclusive start and exclusive end academic year. `DecodedSourceObject` carries one object decoded from stored bytes with its stable source id, canonical group id, change hash and value.

`CurriculumParser` is the family-owned decoding boundary. `decode_objects` turns one stored response into ordered `DecodedSourceObject` records, and it accepts the recorded store as evidence for a family whose response does not name its own period. A family that carries its period ignores that argument, and a family that needs it raises one contract error when it is absent. `read_periods` returns a family's published periods and requires the manifest selection to match them: `SisuParser` reads them from the captured period response, and the three block-driven parsers return the source block's periods, with `GuideParser` keeping only the periods its structure pages publish. `parse_object` converts one replayed object into a normalized course version, module version, or the null-code exclusion provenance. `CurriculumSource` is the neutral driver seam with one `capture_pending` method that records a family's discovery and fetching into the shared checkpoints.

`KoriSource` in `src/course_explorer/ingestion/kori.py` implements `SisuSource` over one synchronous `httpx.Client`. The client is built from `KoriSettings`, whose `kori_base_url` property returns the configured instance's mapped canonical anonymous HTTPS base with no user information, and it never follows a redirect. `_request_json` requires a path that starts with `/api/`, and runs `request_json_with_retries` with `retry_contract_errors=False` and `check_initial=False`, so a malformed successful body is terminal rather than retried and the caller's admission callback owns only the retries. A non-200 status is terminal except a 429 or 5xx status inside the attempt budget, and no error carries response text or a response body.

`_get` paces every transport attempt, retries included. One source-local lock and the monotonic time of the last request start space concurrent request starts by `KORI_REQUEST_INTERVAL_SECONDS`: the wait happens under the lock, the start time is recorded immediately before the request, and the lock is released before the network read. The waits use the client's injected `sleep`.

`PeppiLegacySource` in `src/course_explorer/ingestion/peppi_legacy.py` is the legacy Peppi JSON client. Its `httpx.Client` is built from the configured instance's mapped API origin, its timeout is `KORI_REQUEST_TIMEOUT_SECONDS`, and it never follows a redirect. `_request` requires a path that starts with `/api/`, paces every transport attempt with `KORI_REQUEST_INTERVAL_SECONDS` and the monotonic time of the last start, and runs `request_json_with_retries` with the configured attempt and backoff values. `_classify_request_error` maps HTTP 404 to `PeppiLegacyNotFound` and every other failure to `PeppiLegacyRequestError`, so an optional discovery route reports an absent combination while a required route fails. `_optional_request` returns `None` for that not-found answer. Every source identity inside a request path is percent-quoted, and `walk_nodes` yields one curriculum tree in pre-order while refusing a value that is neither a node object nor a node list.

`PeppiPsgSource` in `src/course_explorer/ingestion/peppi_psg.py` is the Peppi Solenovo PSG JSON client. Its `httpx.Client` is built from the configured instance's mapped API origin, its timeout is `KORI_REQUEST_TIMEOUT_SECONDS`, and it never follows a redirect. `_request` requires a path that starts with `/app/rest/`, paces every transport attempt with `KORI_REQUEST_INTERVAL_SECONDS` and the monotonic time of the last start, and runs `request_json_with_retries` with the configured attempt and backoff values. Every PSG route is required, so an HTTP 404 raises `PeppiPsgRequestError` like every other failed request, and a successful body outside the source contract raises `PeppiPsgContractError`. The client methods read the published years, the education types of one year, one education type's degree programmes, one degree programme's groups, one accomplishment plan's learning units, and one learning unit's detail. Every source identity inside a request path is percent-quoted.

`GuideSource` in `src/course_explorer/ingestion/guide.py` is the guide HTML client over one page transport. `GuidePageTransport` is the seam, and its `get` returns one `httpx.Response` for one guide page path. The plain branch builds an `httpx.Client` from the configured instance's mapped guide origin, its timeout is `KORI_REQUEST_TIMEOUT_SECONDS`, it sends the fixed `course-explorer-guide/1` client identity, and it never follows a redirect.

The browser branch reads through `GuideBrowserTransport` in `src/course_explorer/ingestion/guide_browser.py`, which renders one page at a time in one ephemeral headless Chromium context that sets the Finnish interface locale `fi-FI` and keeps no persistent profile. The page language is read from the page it renders. The browser keeps certificate verification on, and a rendered final path other than the requested same-origin path raises `GuideContractError`. A Playwright error becomes an `httpx.TransportError`, so the shared retry owner keeps the attempt budget. `GuideBrowserTransport.get` closes the page it opened after its request, and the transport closes the context, the browser and the driver on every exit. `GuideSource` closes only the HTTP client it created.

`get_page` requires a path that starts with `/`, paces every transport attempt with `KORI_REQUEST_INTERVAL_SECONDS` and the monotonic time of the last start, and runs `request_json_with_retries` with the configured attempt and backoff values. It requires a `text/html` response, decodes its UTF-8 body, and raises `GuideServerError` when the page keeps answering HTTP 500 after the attempt budget, `GuideRequestError` for every other failed request and `GuideContractError` for a body outside the contract. `guide_path` requires an absolute URL on the configured origin with no credentials and no query, so every discovery belongs to the one guide origin.

`discover_programme_paths` keeps the leaf programme and category paths of the primary language that have one to six path segments and contain a digit, ignores a root link outside those shapes, and returns the kept paths sorted. A root with no kept link fails with `GuideContractError("guide root links no programme page")`. `discover_structure_links` keeps the structure pages of a programme page's year groups at the shallowest published depth, `discover_course_links` keeps the distinct course rows of a structure page sorted by code, and `structure_rows` reads exactly the one published `opas_rakenne` table and is the one table-row walk shared by discovery and decoding.

The adapter refuses every shape it cannot prove.

- `get_curriculum_periods` keeps the source periods whose `activePeriod.startDate` year lies between the mapped first academic year and `CURRENT_ACADEMIC_YEAR`, refuses two periods that share one academic year, returns the selected periods in year order, and refuses an empty selection.
- A search response carrying an `ERROR` notification is refused, as is a truncated response that carries items or a non-positive total.
- A truncated course or module query is partitioned over `_PARTITION_ALPHABET`, which holds `A` to `Z`, `Å`, `Ä`, `Ö` and the digits, up to `KORI_MAX_PARTITION_DEPTH`, and a truncated leaf at that depth is refused. `_validate_search_items` requires every item to name the requested period and, for a course partition, to carry a code matching the partition prefix.
- `_iter_paginated_pages` refuses a page whose `start` or `total` drifts from the first page, a page that makes no progress, a duplicate id inside one query, and an accumulated count above the reported total. `_iter_version_refs` refuses a course id that appears in two disjoint partitions and, when the root query was truncated, a partition union below its broad total.
- `_fetch_exact_batch` refuses a response whose id set differs from the requested ids and a response with a duplicate id. `_validate_group_objects` refuses an item from a different group and a duplicate id.
- `_iter_concurrently` submits one window of `KORI_CONCURRENCY` items at a time and submits the next window only when the consumer advances, so a stopped frontier is never queued.

`capture_curriculum` in `src/course_explorer/ingestion/capture.py` runs the shared phases. It requires `checkpoint_response_count >= 1`, then `_reconcile_manifest` verifies the stored responses and repairs the database provenance through `CapturePersistence.ensure_run` and `register_responses` in bounded batches. A completed manifest is verified against the run row through `verify_run` and reported as it stands. Otherwise `mark_running` transitions the manifest and `source.capture_pending` runs the configured family's discovery and fetching into the shared checkpoints. `next_controlled_batch` consults the `CaptureBoundary` gate immediately before it consumes from a source iterator, and a rejected gate returns `None` and leaves the manifest in its running state.

`src/course_explorer/ingestion/sisu_capture.py` implements `SisuCapture` on that seam. It seeds its invocation-local `_CaptureState` from the verified manifest, records the periods and course and module reference queries per period, fetches the discovered ids that no captured object represents, and closes the pending typed references round by round in sorted order, so a reference cycle terminates.

`SisuCapture` checkpoints its evidence through `record_responses` and `next_controlled_batch` in `src/course_explorer/ingestion/capture.py`, the two helpers that serve every family driver. `src/course_explorer/ingestion/references.py` is the Sisu reference extractor: `extract_course_references` reads the compulsory and recommended formal prerequisite groups and the substitution options, and `extract_module_references` walks the typed rule tree through `CompositeRule`, `CreditsRule`, and `CourseUnitCountRule` children. Both refuse a missing or blank group identity, a member type other than `CourseUnit` or `Module`, a mismatched group field, and an unknown rule type. A fetched group with no objects is kept as an unresolved identity of its own type.

`src/course_explorer/ingestion/peppi_legacy_capture.py` implements `PeppiLegacyCapture` on the same seam. It records every mapped period in block order, then walks the configured discovery variant for each period and records every successful response in checkpoints of one object type.

The navigation entries and an organisation's education types do not depend on the period, so each is read once and reused. An organisation walk fetches the navigation entries, each top-level organisation and its nested units, and the education route of every organisation and navigation entry for that period. The navigation-education-type walk fetches the education route of every navigation entry, and the education-type walk fetches each organisation's education types and their routes.

Education objects and programme nodes are deduplicated by id, a programme tree is recorded as module evidence, and each distinct course detail is fetched once per period and code in sorted order. It seeds the request keys of the course details the manifest already holds, so a resumed capture fetches only the missing ones, and it refuses one course code with two different path ids in one period.

A 404 on a discovery route records no evidence. A course detail that answers 404 for one listed period stores no version for that period, and the unresolved identity is the plan code the programme tree publishes only when no listed period serves it. A 404 on a programme tree or any other course-detail failure fails the run. The shared reference closure accepts that code as a module-rule course reference.

The unresolved set is held in the plan-code space: a course resolves when the request key for its plan code is recorded in any listed period, and the parser maps the request path id to the detail's official code, so a course whose official code differs from its plan code is not reported unresolved. A plan response that holds more than one tree is refused. A resumed capture skips a recorded detail, re-requests a detail of a period it had not finished, and keeps an unresolved code it already recorded.

`src/course_explorer/ingestion/peppi_psg_capture.py` implements `PeppiPsgCapture` on the same seam. It records every mapped year in block order, then walks one fixed discovery chain for each year: the published years, the education types of each listed year, each education type's degree programmes, one group read for every education-type and degree-programme pair, and each group's accomplishment plans. A degree programme that appears under several education types is read once for each pair, because each listing can carry its own groups and plans. Plans are deduplicated by plan id, and a plan listed under several years is fetched once. The years must carry every mapped year.

The degree-programme and group responses are evidence only and store no module. The driver hands the plan-to-listing-year evidence to the parser before any plan response is recorded. Every plan is recorded before any course detail, each plan's course entries supply the course code to learning-unit id map, and each distinct course detail is fetched once in sorted code order. It seeds the request keys of the course details the manifest already holds, so a resumed capture fetches only the missing ones, and it refuses one course code with two learning-unit ids. The source publishes no optional route, so a 404 fails the run.

`src/course_explorer/ingestion/guide_capture.py` implements `GuideCapture` on the same seam. It starts at the guide root, keeps the programme and category links it publishes, reads each programme page's year groups, and reads one structure page per group. The root and programme pages are recorded as evidence-only responses. Every structure page is recorded as module evidence before any course page, and every course page is recorded as one course object. A course page is fetched once per code because a guide course page carries no period.

The selected periods are the distinct year groups the structure pages publish, and a structure year that spans more than one academic year or lies outside the map fails the run. The driver reads a page the manifest already records from its stored bytes, so a reopened store re-reads its recorded pages and fetches only the pages it lacks.

A course page that keeps answering HTTP 500 after the attempt budget, or answers HTTP 200 with the guide's own server-error page, stores no version for that code, is recorded once as an unresolved course reference, and the run completes. The HTTP 200 case is a page whose title contains `Server Error` or whose heading contains `500`, with no recognized course label. The reference closure accepts the recorded code as a module-rule course reference, and every other page failure fails the run.

The service finishes by verifying the stored responses this invocation added through `RawCaptureStore.verify`, calling `mark_completed`, publishing that completed identity through `ensure_run`, and running the final directory verification.

After that final directory verification it runs the completed-state `verify_run` against the stored manifest and run row, and the same completed-state `verify_run` runs when an already completed manifest is reconciled.

A real error marks the manifest failed with the exception type only and re-raises, except that an error after completion propagates as it is and a failure-state persistence error is raised as an `ExceptionGroup`.

`CaptureReport` carries the run id, the status, the manifest path, the response count, the distinct course and module object counts, the two unresolved group counts, and the selected period count. The seeded state reuses the store's invocation-local verified prefix, so a resume after the running transition does not rehash retained bytes from zero.

## The capture store and stored responses

`RawCaptureStore` in `src/course_explorer/ingestion/manifest.py` is the only writer of capture evidence. The glossary names one captured file a stored response, and the code and its symbols call it an envelope, which the manifest records as `CapturedResponseRecord.response_path`.

`create`, `open` and `discover_capture_manifests` each require the family `parser`. `create` resolves the raw data root while refusing a symlinked path component, creates `<raw root>/<YYYYmmddTHHMMSSffffffZ>-<run_id>`, and writes the initial running manifest. `open` resolves the manifest below the raw root while refusing a symlinked component or a name other than `manifest.json`, reads its bytes once for parsing and for the store's `manifest_sha256`, and requires its recorded `raw_root_path` to equal the configured root. Opening binds the manifest and verifies no stored response.

`_write_manifest(manifest_path, manifest)` writes a temporary file in the run directory, fsyncs it, renames the temporary file onto `manifest.json`, and fsyncs the directory, so the manifest is published whole or not at all. It returns the SHA-256 of the serialized payload after the durable publication succeeds. `create` supplies that digest to the constructed store, `open` supplies the digest of the bytes it read once, and `_replace_manifest` revalidates the complete model, assigns the returned digest to the store's `manifest_sha256` after the write succeeds, then installs the candidate and drops the invocation-local verified snapshot only when the response list changes.

`checkpoint_responses` refuses a completed run and a checkpoint with duplicate request keys, and accepts one `(CapturedResponse, object type or None)` pair per response. For a request the manifest already records it requires the identical record and re-verifies that stored response.

A stored response the manifest does not already record goes through `_publish_envelope`, which creates the response directory on first use, refuses a stored response for the same request hash that holds different bytes, writes with `open("xb")`, compares the expected bytes when the file appears concurrently, and overwrites nothing.

`_compressed_envelope` is `gzip.compress(body, compresslevel=9, mtime=0)`, so the same body always produces the same bytes. The response path is `responses/<request hash>-<body hash>.json.gz`, where `_request_hash` hashes the canonical JSON form of the request path and its ordered parameters and the body hash comes from the raw bytes.

`_object_records` asks the store's parser to decode one typed response into ordered `DecodedSourceObject` records and converts each into a `CapturedObjectRecord` with its position, source id, group id and source hash. An evidence-only response has no object records and is not decoded.

`verify(*, start_response_index=0, before_response=None)` is the one verification pass. It clamps the requested index to the contiguous prefix this instance already checked, so a reopened store checks from zero while a same-invocation caller continues past the stored responses it verified. It consults `before_response(completed, total)` before each one and returns `False` without touching evidence when the gate refuses. A failing pass leaves the verified snapshot unset, and the response-directory check runs only when every stored response passed.

`_verify_envelope` refuses a symlinked path, a response path that does not match the manifest's request and body hashes, a missing or corrupt file, bytes that are not the deterministic gzip of the body, a body size or hash that differs from the manifest, and a typed body whose parser-decoded positions or hashes differ from the recorded objects. `_verify_response_directory` refuses a non-file entry, an invalid stored-response name, a corrupt orphan, an orphan that is not deterministic gzip, and an orphan whose body hash does not match its name. A completed manifest additionally refuses a file that is not a stored response, an unreferenced stored response, and a set of stored responses that differs from the manifest.

`iter_responses` verifies the current manifest once and then streams its stored responses, and `iter_objects` decodes each typed response through the parser and yields each object at its decoded position with its record and value. `discover_capture_manifests` returns the `manifest.json` path of every direct run directory while refusing a non-directory entry or a symlink and strictly opening each candidate with the supplied parser. `prune_capture_runs` refuses a raw root that overlaps `data/backups`, refuses a retained manifest that is not one direct run's `manifest.json`, validates every entry as a non-symlink directory before removing anything, and deletes every other run directory.

## The manifest

`CaptureManifest` fixes the retained evidence contract. `format_version` is the literal `2`, so a retained manifest of any other version fails to parse. The manifest carries the run id, the status, the start and finish times, the raw root path, the selected periods, the response records, both unresolved identity tuples, the failure type, and the three capture-scope fields `course_version_limit`, `seed_course_version_ids`, and `seed_selection_complete`, which must be empty or `None`.

The validators refuse a bounded or seeded manifest, a running manifest with a finish time or a failure type, a completed manifest without a finish time, a failed manifest without both a finish time and a failure type, a duplicate request key, a duplicate response path, one object identity with two source hashes, a blank or repeated period, an unsorted or repeated unresolved list, a naive or non-UTC time, and a response path outside the versioned stored-response form. `_manifest_json_bytes` serializes with sorted keys and a trailing newline, and encodes each time with microsecond precision and a `Z` suffix.

`CapturedResponseRecord` holds the request path, the ordered request parameters, the response path, the body hash and size, the object type or `None` for an evidence-only response, and its object records. A response with an object type must carry object records of that same type, and an evidence-only response must carry none. `CapturedObjectRecord` holds the object type, the source object id, the source group id, the position inside its response, and the source hash.

## Normalization parsing

`parse_capture(store)` in `src/course_explorer/ingestion/normalization.py` validates one completed capture and uses `store.parser` for its family-specific reading. It calls `parser.read_periods(store)`, which returns the family's published periods and requires the manifest selection to match them. It then replays the objects in stored order and skips a repeated object whose group and hash agree with its first occurrence, while refusing a repeat with a different group or hash. The parser converts each object, and the shared service performs all family-independent work.

`src/course_explorer/ingestion/sisu_normalization.py` holds `SisuParser`. Its `_SourceCourse` and `_SourceModule` model the Sisu fields, and both permit unrelated source fields. A localized field is read as one language-to-value mapping that preserves every supplied language key, null and blank value. A decimal, integer, or date range refuses a minimum above its maximum. A course `code` is required, while a module `code` may be absent or blank and is stored as absent. A course whose `code` is explicitly null returns its `SnapshotProvenance` instead of a version, which `parse_capture` collects in `excluded_null_code_course_versions`. `decode_objects` owns JSON-list decoding, the nonblank source and group identity and the hash of the stored raw object, returning one record per raw item in raw order. `parse_object` validates and converts one replayed Sisu course or module without deduplication, closure or period work. `_module_rule` keeps every non-null language of a localized description.

`src/course_explorer/ingestion/peppi_legacy_normalization.py` holds `PeppiLegacyParser`. `_PeppiCourseRecord` and `_PeppiModuleRecord` are the extracted records, and their source hash covers the record rather than the response, so a request-time value such as `createdAt` never changes it. `_localized` maps `valueFi`, `valueEn` and `valueSv` to `fi`, `en` and `sv` and ignores every other key.

`_extract_texts` maps one course `contentList` onto `outcomes`, `content`, `prerequisite_text` and `additional_info` through the exact observed title vocabulary in Finnish, English and Swedish, joins repeated sections per language with one blank line, and stores nothing for an unmapped title. The course `name` comes from the detail's own name map. A course `credits` number supplies both credit bounds, otherwise the supplied `minCredits` and `maxCredits` values are kept and a missing bound is stored as null.

`_extract_course` and `_extract_modules` derive their record's period from the response's own request, which must carry exactly one published period.

`_extract_modules` walks one programme tree in pre-order, maps `PROGRAMME` to `DegreeProgramme`, `STUDY_MODULE` to `StudyModule`, and `CATEGORY`, `OFFERING`, `COURSE_UNIT_PART` and `GROUPING_MODULE` to `GroupingModule`, and refuses an unknown node type. The tree root keeps its own `<node type>:<code>` identity, and every module below it stores the root identity as its owning programme. The record and its source hash carry that owning identity.

A course version identity is the official code with its request's period, and its canonical group identity is the code. A root module's canonical group identity is `<root node type>:<root code>`, and a nested module's canonical group identity is `<root node type>:<root code>:<node type>:<code>`. A module version identity adds `|<period>` to its canonical group identity. The node type is the source token exactly as published. The stored and displayed module code is the official code without the type prefix.

A module-rule child that is a module references its scoped module group identity, computed with the same owning programme, and a course-unit child references the official code of the course detail fetched for its path id, falling back to its published plan code when no detail was captured. The official URL is the first official language's template with the quoted code, quoted path id and the record's period. A course stores no document state, no validity period, no revision, no prerequisite option and no substitution option.

`read_periods` returns every mapped published period and requires the manifest selection to match them.

`_module_rule` maps `ALL_OF` to an all-mandatory composite, `ONE_OF` to a composite that requires one child, `SOME_OF`, `NUMBER_OF` and `ECTS` to a credits rule over one non-mandatory composite child with the node's credit bounds, and a null optionality or a missing credit minimum to a non-mandatory composite with a minimum of zero and no maximum. A `NUMBER_OF` node publishes no child count, only its own credit bounds and children whose individual credits fall below or above those bounds, so those published credit bounds determine the one credit rule over one selection pool. It numbers each child by its position.

`src/course_explorer/ingestion/peppi_psg_normalization.py` holds `PeppiPsgParser`. `_PeppiPsgCourseRecord` and `_PeppiPsgModuleRecord` are the extracted records, and their source hash covers the record rather than the response.

The plan response is the authoritative source of the tree. Its flat entries carry a `level`, an `orderNumber` and the learning unit, and the parser sorts them by `orderNumber`, requires distinct numbers and requires the lowest one at level 1. An entry's parent is the nearest earlier entry with a lower level, and the entries at level 1 are the structure roots. A plan response has no programme root module, so the plan id is the tree identity and every record, including a level-1 root, stores `PLAN:<plan id>` as its owning identity. The record and its source hash carry that owner.

`STUDY_MODULE` maps to `StudyModule`, and `CATEGORY` and `OFFERING` to `GroupingModule`. A module rule is a non-mandatory composite rule with `require_min` zero, no maximum, null credit, count and description fields, and one child per direct child. A plan response names no year, so its listing years come from the recorded group responses, whose paths carry the year and whose plans list the plan ids. A plan listed under several years supplies one module record per listing year, and the plan credit is joined per year and learning-unit id. An empty plan publishes no structure and supplies no record.

A course version identity is the official code with its listing year's period, and its canonical group identity is the code. A module's canonical group identity is `PLAN:<plan id>:<source type>:<code>`, and its version identity adds `|<period>`. The stored module code is the official code without the type prefix, and a module-rule child references a course by its code and a module by its plan-scoped identity.

The detail response supplies a course's name, outcomes and content, and the plan response supplies its plan credit for each listing year. A course detail is decoded only after the plans that list it, and one learning unit with two plan credits in one year fails the capture. The detail's own credit wins when it carries one, otherwise that year's plan credit is used, and a course with neither stores no credit. `_localized` keeps the configured official languages of a bare language map. The official URL is the first official language's course-description template with the quoted learning-unit id. A course stores no document state, no validity period, no revision, no prerequisite option and no substitution option.

`read_periods` derives every plan's listing years from the recorded group responses, joins its plan credits, returns every mapped year and requires the manifest selection to match them.

`src/course_explorer/ingestion/guide_normalization.py` holds `GuideParser`. `_GuideCourseRecord` and `_GuideModuleRecord` are the extracted records, and their source hash covers the record, including the full-ancestor-scoped group id, the null-or-official code, the count bounds and a nested module's owned children, rather than the page bytes. The parser reads the recorded root and programme evidence to recover each structure page's period, programme code and year heading, and reads the structure page's own published programme code when the year group carries none, because a guide request carries no period or programme parameter. Both guide fetch variants return the same HTTP-shaped page response, so the one parser reads the plain-HTTP body and the rendered DOM alike.

A structure page publishes exactly one `opas_rakenne` structure table, and its rows carry a level, a node type, an official code, a name, an optionality phrase and credit bounds. The timing and classification tables describe display order and supply no curriculum row, and duplicate timing views under one programme code decode to identical records. A published table with only its header row is an empty structure and supplies no module or course record. A row's parent is the nearest earlier row with a lower level, and the level-1 rows are the programme root's children. `STUDY_MODULE` maps to `StudyModule`, and `CATEGORY`, `OFFERING`, `GROUPING_MODULE` and `COURSE_UNIT_PART` map to `GroupingModule`.

The synthesized programme root is `PROGRAMME:<root code>`, where the code is the year group's published label, otherwise the structure page's published programme code, otherwise the programme page's last path segment. A nested module is `<parent group id>:<node type>:<published code or name>`, so it carries every parent module's node type and published code or name within the programme, and a module version adds `|<period>`. A module's identity is its published official code when nonblank, otherwise its published name, and its displayed code is the official code or null. A code-less module whose published name repeats among its parent's module children appends its 1-based ordinal among those same-named siblings to the module identity, as in ` #1` and ` #2`, and a name that occurs once carries no ordinal. The stored published name keeps the source's spelling.

A course's canonical identity is its official code and its version identity is `code|period`. A module-rule child references a course by its official code and a module by its full scoped module group identity.

The page language is the first recognized label language, never the requested URL language. The section vocabulary maps Finnish, English and Swedish labels onto the five official text fields, joins repeated sections per language with one blank line, and ignores an unmapped label. The course name is the page's `h1` without a trailing credit marker, and the structure row name is used when the page has no heading. A title whose page-specific part before a trailing ` | <site name>` suffix ends with the listing code, spelled without whitespace, passes the course-title check. Otherwise the check reads the title's trailing guide-shaped code token and refuses a token that does not end with the listing code. A guide-shaped token starts with letters followed by digits and may end with further letters or digits, with at most one space and no hyphen, and a title with no such token passes.

The official URL is the first structure link's absolute URL. A course stores no document state, no validity period, no revision, no prerequisite option and no substitution option. `read_periods` returns the periods the published year groups name and requires the manifest selection to match them.

The one optionality vocabulary reads the Finnish, English and Swedish phrases. `_module_rule` maps `ALL_OF` to an all-mandatory composite and `ONE_OF` to a composite requiring one child. The published course-count phrase becomes a course-unit count rule over one non-mandatory composite child, carrying its published minimum and maximum. A zero-minimum course-count range such as `Valitaan (kpl): 0-75` becomes a non-mandatory composite with a minimum of zero and the published maximum, and a published zero count such as `Valitaan (kpl): 0` becomes a non-mandatory composite with a minimum of zero and no maximum. A credit-selection or separate-criteria phrase (`SOME_OF`) with a published credit minimum becomes a credits rule over one non-mandatory composite child with the module's credit bounds. A `SOME_OF` without a credit minimum, the Swedish `Väljs efter separata kriterier` and a null optionality become a non-mandatory composite with a minimum of zero and no maximum.

`SourcePeriod` requires a positive start and an end after the start at the family input boundary. A one-year period keeps its source id. A multi-year `[start, end)` expands to one `NormalizedPeriod` per academic year with id `f"{source_id}:{year}-{year + 1}"`, and a source membership expands to those ids in year order. The shared service deduplicates resulting memberships in first-occurrence order and rejects conflicting duplicate period ids. A source membership naming a period absent from the captured period response is dropped before expansion and counted once per source membership, not once per year. The version itself is kept, including a version whose memberships are all dropped. A null-code excluded course contributes no dropped count.

The official URL is built by `SisuParser` from the configured instance's mapped course-guide base, which `validate_course_guide_base_url` accepts only from the finite map, and the percent-quoted source object id, so an id with reserved characters never splits the path.

The Sisu parser validates module rules as `CompositeRule`, `CreditsRule`, `CourseUnitCountRule`, `CourseUnitRule`, `ModuleRule`, `AnyCourseUnitRule`, or `AnyModuleRule`, and each shape refuses an unknown field. `_module_rule` maps a composite `require` range to `require_min` and `require_max`, a credits range to `credits_min` and `credits_max`, and a count range to `count_min` and `count_max`, keeps the present languages of a localized description, and numbers children by their position. `walk_normalized_rule` yields a tree depth-first.

`_validate_reference_closure` refuses represented and explicitly unresolved identities that overlap, a course prerequisite or substitution reference that is neither represented nor excluded nor explicitly unresolved, a module reference that is neither represented nor explicitly unresolved, and a module rule node that references an identity outside the corresponding closure.

`NormalizationBatch` carries the run id, the published periods, the covered period ids, the course versions, the null-code exclusions, the module versions, the two unresolved tuples, and the dropped-membership count. `parse_capture` derives the covered ids by expanding only the selected capture periods from the manifest, so a published period outside the capture interval is a membership source without being reconciled by this run.

`NormalizationReport` reports the dropped count as `dropped_period_membership_count`, and `IngestionProgress` carries it after a completed normalization so the ingestion status reports it. `normalize_curriculum` parses the whole capture and then calls `NormalizationPersistence.apply` once.

## The normalization transaction

`NormalizationRepository.apply` requires a positive current academic year and window, loads the completed `IngestionRun`, and checks every batch provenance against the run's source snapshots through `_load_snapshots`, which refuses a missing snapshot or one whose type, object id, group id, or hash conflicts. The normalization id loaders reach their statements in chunks of 10000, because one PostgreSQL statement carries at most 65535 bind parameters and a supported university's version set exceeds that. `_prepare_periods` creates or updates the period rows, and `_ensure_owners` inserts the missing canonical course and module rows, and a course row created by the batch starts inactive and carries the batch's year and window.

`_apply_versions` reconciles one object type. The exact version identity column is `source_version_id`, and a course minimum credit and both exact-version document-state columns may be null when the source publishes no value.

When the stored snapshot hash equals the normalized source hash the version is classified `unchanged` and no row or payload is written, so a retained official cell keeps its stored bytes even where the write policy suppresses that value.

Otherwise the version is classified `changed`, its official cells and rule payload is deleted through `_delete_version_payload`, and its fields are updated in place with the batch's snapshot, so the version retains its primary key. A source id with no stored row is inserted.

`_insert_version_payload` writes the official course cells or module name cells and the prerequisite and substitution options, or the module rule tree, with `_insert_rule_tree` writing one node per tree node. An exact source id linked to a different canonical group raises `ValueError`.

The writer filters each official field against the configured university's ordered `official_languages`. It keeps the first nonblank exact value for a language and suppresses a value that repeats one already kept on the same field. It ignores a supplied language the map does not configure, preserves the bytes of every kept value, and compares no other field, version or course. The parser retains every supplied language. Only this writer applies the configured-language filter and the ordered duplicate rule.

`_reconcile_period_memberships` owns the listing contract for both object types. For every covered period it deletes the stored memberships whose versions the incoming batch does not list in that period, including all of them when the source lists none. It inserts every incoming membership that is absent, whether the version is `new`, `changed` or `unchanged` and whether the period is covered or outside the coverage. Memberships outside the covered periods that the incoming batch does not name form the stored history.

`_remove_excluded_null_code_versions` deletes the stored version of every excluded source id and then deletes the canonical course when no version of it is stored. `_recalculate_courses` uses grouped SQL to obtain the first and last listed academic year and whether any membership lies inside the activity interval, then writes those values and the stored year and window for every course. A stored inactive-to-active transition calls `InferenceSchedulingRepository.reset_reactivated_processing` in the same transaction, which sets the marker to not processed unless an operator disposition is set. The report returns the exclusion provenance and counts the `new`, `changed`, and `unchanged` classifications per object type.

`_prune_unreferenced_provenance` runs at the end of the same transaction. It deletes every database source snapshot of a completed run that no stored course or module version references, then deletes a completed run that owns no snapshot. A running or failed run, a referenced snapshot and every retained raw evidence file are kept. A failed normalization rolls the cleanup back with the rest of the transaction.

`refresh_course_activity` is the public activity owner for a current-year or window change. It runs the same recalculation over every stored course in its own transaction and creates no course, membership, result, pointer or receipt.

The whole batch runs inside one `session_scope` transaction, so any raise rolls back every row the batch wrote.

## Composition and lifecycle entry points

`src/course_explorer/ingestion/family.py` is the one process composition owner for the configured university's source family.

`load_curriculum_parser` returns `SisuParser` built from the mapped course-guide base for `source_family="sisu"`, `PeppiLegacyParser` built from the Peppi legacy source block and the mapped official languages for `source_family="peppi_legacy"`, `PeppiPsgParser` built from the Peppi PSG source block and the mapped official languages for `source_family="peppi_psg"`, and `GuideParser` built from the guide source block and the mapped official languages for `source_family="guide"`.

`open_curriculum_source` matches the same family and yields `SisuCapture` over `KoriSource`, `PeppiLegacyCapture` over `PeppiLegacySource`, `PeppiPsgCapture` over `PeppiPsgSource`, or `GuideCapture` over `GuideSource`. For `source_family="guide"` it chooses the plain client or `GuideBrowserTransport` from the block's fetch variant before it builds `GuideSource`. An unsupported family fails at that boundary.

`src/course_explorer/ingestion/commands.py` wires validated settings into the import service. `run_capture_command` loads the capture and normalization settings, resolves the parser once, opens the retained store when `resume_manifest` is given and creates one otherwise with that parser, calls `on_store_selected` immediately after the store exists so a detached worker can bind durable state to the manifest identity, and refuses a negative `verification_start_index`.

`import_curriculum` runs `capture_curriculum` and returns `None` when the controller paused or stopped at a durable boundary. It consults the gate once at `before_normalization` and then runs the one normalization transaction with no further polling, splitting, or interruption.

`CurriculumImportReport` validates that both services report one run id, that the capture completed, that `course_object_count` equals the normalized version count plus the null-code exclusions, that `module_object_count` equals the module version count, and that both unresolved counts agree.

`IngestionStage` in `src/course_explorer_admin/local_stages.py` adapts the command to the lifecycle. `select_options` adopts the sole retained running or failed manifest for a bare start and refuses two candidates. `identity_sha256` hashes the effective source facts, the request shape and the normalization policy that change captured work through `ingestion_configuration_sha256`.

A Sisu payload carries the mapped Kori base, university root identity, first academic year and course-guide base, the remaining Kori request-shape and academic-year values, the normalization policy, and the ordered official languages. A Peppi legacy payload carries the family, API origin, discovery variant, ordered period list and course-page templates with the current academic year and the same normalization policy. A Peppi PSG payload carries the family, API origin, ordered period list and course-page template with the current academic year and the same normalization policy. A guide payload carries the family, guide origin, fetch variant and ordered period list with the current academic year and the same normalization policy.

The Sisu-only request-shape keys `kori_search_page_size`, `kori_batch_size` and `kori_max_partition_depth` are outside the Peppi and guide payloads. The display fallback, the display label and the instance key are outside every payload, and the operational tuning values `kori_request_timeout_seconds`, `kori_max_attempts`, `kori_retry_backoff_seconds`, `kori_concurrency` and `kori_request_interval_seconds` are outside them too, so a university change changes the identity while pacing does not.

The raw-data root and the capture checkpoint frequency are capture settings, and the hash takes no capture setting.

The stage records the selected store's published `manifest_sha256`, its relative path, and its run id, resets the recorded verification prefix when that digest changes, reports the capture stage, the response counts, the verification counts, and the normalization stage through its progress, and retains the manifest identity that the next bare start continues from.
